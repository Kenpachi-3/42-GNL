# get_next_line

***

# Description
This project is about programming a function that reads a file descriptor and returns one line at a time until the end of the file. 

---

# Instructions

### Building the Library
To compile the source files and create the static library archive `gnl.a`, run the following command in your terminal:
```bash
make
```

### Maintenance Rules
* Remove temporary binary object files (`.o` files):
  ```bash
  make clean
  ```
* Remove object files AND the final compiled `gnl.a` library:
  ```bash
  make fclean
  ```
* Force a complete clean rebuild of the entire library from scratch:
  ```bash
  make re
  ```

### Usage in External Projects
To use `get_next_line` in your own C projects, include the header file in your code and link the static library during compilation:

1. Add the header to your C files:
   ```c
   #include "get_next_line.h"
   ```
2. Compile your project by linking `gnl.a`:
   ```bash
   cc main.c gnl.a -I. -o my_program
   ```

## Algorithm

The `read()` function reads a fixed number of bytes at a time, determined by `BUFFER_SIZE` — it has no concept of "lines," and it disregards how many lines a file descriptor contains. `get_next_line` is called once per line, so it needs a way to remember, between calls, any data it already read but didn't return yet.

This is where a static variable becomes essential: unlike a normal local variable, it persists between function calls instead of being destroyed each time the function returns, retaining its value until the program ends or it's explicitly changed. Its job here is to store the leftover — the part of the buffer that was read but didn't belong to the line just returned — so it can be joined with newly read data on the next call.

Rather than a single static variable or a fixed-size array indexed by file descriptor, this project stores leftovers in a linked list of `{fd, leftover}` pairs. An array would require deciding on a maximum file descriptor count (`FD_MAX`) ahead of time, which isn't always known; a linked list grows and shrinks as needed and handles any number of file descriptors without that limitation.

For each call, the function looks up (or creates) the leftover node for the given fd, then loops: read into the buffer, append the buffer to the leftover, and repeat — until one of three things happens:
- a `'\n'` is found in the accumulated data (a full line is ready),
- `read()` returns `0`, meaning end-of-file has been reached, or
- `read()` returns `-1`, meaning a read error occurred.

If the loop stops because of a read error, the function frees all allocated memory and returns `NULL` immediately, discarding the leftover for that fd.

Otherwise — whether the loop stopped because of a newline or a clean EOF — the accumulated data is split in two: everything up to and including the `'\n'` (or up to the end of the data, if no `'\n'` was found) becomes the line that gets returned, and everything after it is saved back into the linked list as the new leftover for that fd's next call. Once a fd reaches EOF with no leftover remaining, the following call returns `NULL`, signaling there are no more lines to read.
